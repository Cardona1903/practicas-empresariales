# Validación de CU-09: Realizar postulación a la práctica

## Salida de ejecución de la suite de pruebas (`test/probar-postularse.ts`)

```text
================================================================
 EJECUTANDO PRUEBAS DE VALIDACIÓN: CU-09 POSTULARSE A LA PRÁCTICA
================================================================

TEST 1: Carga exitosa de postulación con requisitos completos (flujo básico)
  -> RESULTADO: CUMPLE (HTTP 201, postulación creada en estado explícito RECIBIDA, sin transiciones automáticas)

TEST 2: Rechazo de postulación por documentos incompletos (flujo alterno)
  -> RESULTADO: CUMPLE (HTTP 422, rechazo inmediato por documentación incompleta, 0 inserciones en BD)

TEST 3: Rechazo de postulación por archivo corrupto o ilegible (flujo alterno)
  -> RESULTADO: CUMPLE (HTTP 422, rechazo por archivo corrupto sin cabecera PDF válida)

TEST 4: Intento de postulación cuando ya existe una postulación activa (flujo alterno)
  -> RESULTADO: CUMPLE (HTTP 409 Conflict, rechaza trámite simultáneo si ya existe postulación activa)

TEST 5: Bloqueo de postulación sin autenticación o rol indebido (EAC-03 Seguridad)
  -> RESULTADO: CUMPLE (100% accesos bloqueados con HTTP 401/403, 3 eventos en auditoría con latencia < 1 s)

TEST 6: Modificación de requisitos sin tocar código ni redesplegar (EAC-02 Mantenibilidad)
  -> RESULTADO: CUMPLE (HTTP 422, reconoce regla modificada en base de datos sin alterar código de postulación)

================================================================
 RESUMEN DE PRUEBAS: 6/6 ESCENARIOS CUMPLIDOS
================================================================
```
